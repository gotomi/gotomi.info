# gotomi.info

Personal site of Tomasz Gospodarczyk — built with [Astro](https://astro.build/) and
[Svelte](https://svelte.dev/), deployed as a static site on Netlify.

## Requirements

- Node.js **>= 22.23.4** (see `.nvmrc`)
- npm

## Setup

```bash
nvm use
npm ci
npm run dev
```

The dev server runs at `http://localhost:4321`.

## Scripts

| Script                               | Description                                         |
| ------------------------------------ | --------------------------------------------------- |
| `npm run dev`                        | Start the Astro dev server                          |
| `npm run build`                      | Build the static site to `dist/`                    |
| `npm run preview`                    | Preview the production build locally                |
| `npm run check`                      | Run `astro check` and `svelte-check`                |
| `npm run check-and-build`            | Type-check and build (used by CI)                   |
| `npm run format`                     | Format the repository with Prettier                 |
| `npm run format:check`               | Verify formatting without writing                   |
| `npm run data:gallery -- <slug>`     | Regenerate one gallery JSON and its derivatives     |
| `npm run data:gallery:all`           | Regenerate all galleries                            |
| `npm run data:instagram`             | Download photos from Instagram                      |
| `npm run data:instagram:derivatives` | Regenerate Instagram WebP derivatives from `media/` |
| `npm run data:photos`                | Regenerate `/photos` WebP derivatives from `media/` |

## Media and generated assets

The repository keeps source media and generated, web-optimised derivatives apart:

```
media/                     # originals, not deployed
  gallery/<slug>/*.jpg
  instagram/**/*
  photos/*

public/                    # deployed as-is
  gallery/<slug>/normal/*.webp
  gallery/<slug>/thumbnails/*.jpg
  instagram/**/*-400.webp
  instagram/**/*.mp4
  photos/*.webp
```

- **Originals live in `media/`** and are committed to the repository (no Git LFS).
- **Derivatives live in `public/`** and are committed too, so Netlify builds do not
  need to process hundreds of images.
- Gallery `normal/` images are WebP (height 1500 px); thumbnails stay JPG (height 300 px).
- Instagram grid images are WebP, 400 px wide. Videos are copied as MP4.
- `/photos` images are WebP, 400 px wide.

### Adding or updating a gallery

1. Put the original JPG/PNG files in `media/gallery/<slug>/`.
2. Run `npm run data:gallery -- <slug>` (or `npm run data:gallery:all`).
3. Commit both `media/gallery/<slug>/` and `public/gallery/<slug>/`, plus
   `src/_data/galleries/<slug>.json`.

### Instagram

`scripts/fetch-instagram.mjs` downloads originals to `media/photos` and writes
`src/_data/photos.json`. `scripts/generate-instagram.mjs` rebuilds the grid
derivatives in `public/instagram` from the originals listed in
`src/_data/instagram.json`.

The download script uses a private endpoint and is **not** part of the build. It
requires credentials in the environment (see `.env.example`):

```bash
cp .env.example .env
# fill in IG_APP_ID, IG_CSRF_TOKEN, IG_CLAIM
npm run data:instagram
```

This approach is fragile and may violate Instagram's terms of service. Prefer the
official API or a manual export when possible. Never commit real credentials.

## Data

Content lives in `src/_data`:

- `galleries/*.json` — generated by `scripts/generate-gallery.mjs`.
- `photos.json` — generated by `scripts/fetch-instagram.mjs`.
- `instagram.json` — feed used by `/instagram/` and `/after/`; updated by
  `scripts/generate-instagram.mjs`.
- `music.json`, `projects.json` — maintained manually.

`src/lib/data.ts` validates the imported JSON at build time, so a malformed data
file fails the build with a readable error instead of breaking a component.

## Deploy

Netlify reads `netlify.toml`:

- build command: `npm run build`
- publish directory: `dist`
- Node.js 22
- security headers (CSP, `nosniff`, `Referrer-Policy`, `Permissions-Policy`)
- cache headers: hashed `/_astro/*` assets are immutable, media is cached for 7 days

Every pull request should be verified on a Netlify deploy preview before merging.

## Project structure

```
src/
  components/   Astro and Svelte components
  layouts/      BaseHead, Layout
  lib/          Typed data access and validation
  pages/        Routes (/, /after/, /instagram/, /marta/, 404)
  style/        Global CSS
  types/        Shared TypeScript types
scripts/        Gallery/Instagram/photo pipelines
media/          Source media (committed, not deployed)
public/         Generated and static assets served as-is
```

## Quality checks

CI (`.github/workflows/ci.yml`) runs on every push and pull request:

```bash
npm ci
npm run check-and-build
npm run format:check
npm audit --audit-level=high
```

Keep `npm run check-and-build` green locally before opening a PR.
